# Сервер «Лаборатории Сириус»

Сейчас сервер работает на Supabase (регион eu-north-1, Стокгольм). Всё устройство сервера — в файлах
`schema.sql` (классы, ученики, работы, журнал) `tests.sql` (тесты учителя), `stats.sql` (счётчик посещений) `applications.sql` (заявки учителей) `accounts.sql` (удаление аккаунта) и `observe.sql` (просмотр учителей администратором): таблицы (схема `lab`, снаружи закрыта) и функции, которые вызывает сайт
(`POST /rest/v1/rpc/<функция>`). Вход учителей и учеников сделан на самих функциях, без Supabase Auth,
поэтому сервер можно перенести на любой хостинг.

## Что хранится

* учителя: почта, имя, пароль (только bcrypt-хэш);
* приглашения для регистрации учителей;
* заявки учителей: имя, почта, школа, классы, комментарий, решение (IP — только хэш);
* классы и ученики: только имя (без фамилии), личный код и отметка устройства;
* открытые классу работы и сроки сдачи;
* результаты: показания приборов, мини-тест, время работы;
* тесты учителя и попытки учеников: выбранные вопросы, ответы, баллы, число уходов со страницы.

## Как перенести на свой сервер (например, в России)

1. Поставьте PostgreSQL 15+ и PostgREST (или используйте хостинг, где они есть).
2. Создайте роли `anon` и `authenticated` (PostgREST работает от `anon`) и выполните `schema.sql`, затем `tests.sql`, `stats.sql`, `applications.sql`, `accounts.sql` и `observe.sql`.
3. Перенесите данные: `pg_dump --schema=lab` со старого сервера и загрузка на новый.
4. В `index.html` поменяйте адрес и ключ в строке `const API=…` и запустите `python3 tools/build_en.py`.

## Первое приглашение администратора

Если база пустая, первое приглашение создаётся вручную:

```sql
insert into lab.invites(code, note, is_admin, expires_at)
values (lab.rand_code(4) || '-' || lab.rand_code(4), 'Авторы проекта', true, now() + interval '30 days')
returning code;
```

Дальше администраторы создают приглашения для учителей прямо в кабинете на сайте
или одобряют заявки, которые учителя оставляют на странице учителя.
