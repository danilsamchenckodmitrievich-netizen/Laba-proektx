# Обучение OCR Аксиоры в Google Colab

Этот этап готовит данные, дообучает компактный **TrOCR-small (61,6 млн параметров)** и автоматически
загружает результат на Hugging Face Hub. Основной профиль рассчитан на одну T4 с примерно 15 ГБ VRAM.
Полноценное обучение выполняется пользователем в Colab; наличие ноутбуков само по себе не означает,
что математический OCR уже обучен и готов проверять работы учеников.

## Открыть ноутбуки

**Для полного запуска одной командой:** [открыть единый ноутбук](https://colab.research.google.com/github/danilsamchenckodmitrievich-netizen/Laba-proektx/blob/main/notebooks/00_run_ocr_end_to_end.ipynb).
Выберите T4, разрешите Drive и доступ к `HF_TOKEN`, затем **Среда выполнения → Выполнить все**.
Если ZIP отсутствует, данные подготовятся автоматически; если есть совместимый checkpoint — обучение продолжится.
Отсутствующий или недоступный `HF_TOKEN` не останавливает обучение: готовые веса сохраняются на Drive,
а отправка на Hub откладывается. При этом варианте T4-сессия используется и во время подготовки данных;
для экономии GPU-времени можно выбрать раздельные ноутбуки ниже.
Чат ChatGPT можно закрыть после старта. Сама вкладка Colab должна оставаться открытой, если ваш тариф
не предоставляет фоновое выполнение; бессрочная работа не гарантируется. [Условия Colab](https://research.google.com/colaboratory/faq.html).

Для раздельной подготовки на CPU и обучения на GPU:

1. [Подготовить данные в Colab](https://colab.research.google.com/github/danilsamchenckodmitrievich-netizen/Laba-proektx/blob/main/notebooks/01_prepare_ocr_dataset.ipynb).
2. [Обучить модель и выгрузить веса в Colab](https://colab.research.google.com/github/danilsamchenckodmitrievich-netizen/Laba-proektx/blob/main/notebooks/02_train_ocr_colab.ipynb).

Запускайте ячейки сверху вниз. Для первого ноутбука достаточно CPU; во втором выберите
**Среда выполнения → Сменить среду выполнения → T4 GPU**.

## Порядок запуска

1. В первом ноутбуке оставьте `DATASET_VARIANT = "full"` для реального обучения.
   Скачивается исходный архив около 2,9 ГБ; по умолчанию готовятся 12 000 train, 1000 validation и 500 test.
   Дополнительно создаётся до 300 печатных примеров только для train. Для быстрой проверки есть `excerpt`.
2. Просмотрите изображения и соответствующие подписи. Итоговый `axiora-ocr-dataset.zip` и его SHA-256
   сохранятся в `MyDrive/Axiora/ocr/`. Исходный большой архив остаётся на временном диске Colab.
3. На Hugging Face создайте [токен](https://huggingface.co/settings/tokens) с правом записи в ваш
   репозиторий моделей. В разделе **Секреты** Colab добавьте его под именем `HF_TOKEN` и разрешите доступ ноутбуку.
4. Во втором ноутбуке используйте `RUN_MODE = "t4"`. Он восстановит данные из Drive и проверит их целостность.
5. Дождитесь обучения, итоговой оценки и CPU-проверки. Контрольные точки и экспорт сохраняются на Drive.
6. Последняя ячейка автоматически выполнит `model.push_to_hub`, выгрузит согласованный процессор и отчёты.
   Если `HUB_REPO_ID = None`, имя будет `<ваш-HF-логин>/axiora-ocr`. По умолчанию репозиторий приватный.
7. Сохраните выведенные **repo_id и revision**: они понадобятся backend на следующем этапе.

Google-аккаунт и аккаунт Hugging Face независимы. Значение `HF_TOKEN` не вставляется в текст ноутбука,
не выводится на экран и не входит в экспорт. Изображения и optimizer-checkpoints на Hub автоматически не отправляются.

## Быстрая проверка и возобновление

Для проверки инфраструктуры выберите в первом ноутбуке `excerpt`, а во втором — `RUN_MODE = "smoke"`.
Скачивается лишь около 1,5 МБ исходных InkML, выполняются два optimizer шага. Такие веса загружаются
в отдельный репозиторий с суффиксом `-smoke`: применять их к решениям учеников нельзя.

При обрыве Colab откройте второй ноутбук заново с теми же `RUN_NAME`, данными и настройками, оставив `RESUME = True`.
Восстанавливаются веса, optimizer, scheduler и генераторы случайных чисел. При изменении данных, кода обучения
или гиперпараметров выберите новое имя запуска: смешивать несовместимые контрольные точки нельзя.

Если обучение закончено, а отправка на Hub прервалась, повторите последнюю ячейку. В новой CPU-сессии достаточно
выполнить установку, настройки, подключение Drive и последнюю ячейку: она сама загружает готовый экспорт с диска.
Повторно обучать модель для выгрузки не требуется.

## Источники данных и права

Используются реальные человеческие штрихи [Google MathWriting](https://github.com/google-research/google-research/tree/master/mathwriting),
которые растеризуются в изображения. Источник разметки — `normalizedLabel`, а не произвольное название файла.
Сохраняются официальные train/valid/test. Writer ID не опубликованы; исходное разбиение не гарантирует,
что каждый автор встречается только в одной выборке. Идентичные растровые изображения дополнительно удаляются.

MathWriting: **CC BY-NC-SA 4.0**, Google LLC. Часть исходных LaTeX-выражений из Wikipedia имеет условия CC BY-SA.
Стандартный сценарий предназначен для некоммерческого использования; карточка модели сохраняет эти ограничения
и ссылки на источник. Для коммерческого сценария нужен отдельный набор с подходящими правами.

### Собственные фотографии

Подготовьте UTF-8 JSONL, например:

```json
{"image":"images/formula-01.jpg","latex":"3x+5=26","group_id":"writer-a-session-1","split":"train"}
{"image":"images/formula-02.jpg","latex":"\\frac{1}{2}","group_id":"writer-b-session-1","split":"validation"}
{"image":"images/formula-03.jpg","latex":"F=mg","group_id":"writer-c-session-1","split":"test"}
```

Одна строка — одна вырезанная формула, а не страница тетради. Путь относителен каталогу JSONL.
Во всех строках одного автора/сессии используйте один `group_id`. При отсутствии `split` применяется
стабильное разделение групп 80/10/10; для малого числа авторов лучше задать три выборки явно.
Заполните `CUSTOM_MANIFEST` и `CUSTOM_LICENSE` в первом ноутбуке. Можно сочетать свои фото с MathWriting
или выбрать `DATASET_VARIANT = "none"` и использовать только свои данные.

## Что сохраняется с моделью

| Артефакт | Назначение |
|---|---|
| `model.safetensors`, `config.json`, `generation_config.json` | Полные веса и настройки компактного encoder/decoder |
| Файлы процессора и токенизатора | Та же обработка пикселей и LaTeX-словарь, что при обучении |
| `axiora_preprocessing.json` | EXIF, белый фон для alpha, обрезка пустых полей и letterbox 384×384 |
| `training_report.json` | Метрики, отпечатки данных и кода, версии, число исключённых подписей и VRAM |
| `cpu_benchmark.json` | Холодная загрузка, тёплые median/p95, длина генерации, RAM, FP32/INT8 и изменение качества |
| `README.md` | Карточка модели, источники, лицензии, ограничения и правила применения |

Токенизатор исходного TrOCR-small поддерживает стандартные LaTeX-команды. Подписи, которые содержат
неизвестные токены или не помещаются в 128 токенов, не обрезаются: они явно исключаются с отдельным счётчиком.
Это ограничивает область метрик короткими поддерживаемыми формулами и должно учитываться при оценке качества.

## Как читать результаты

- **CER** — доля ошибок символов; ниже лучше, при множестве лишних символов значение может быть больше 1.
- **Exact match** — доля полностью совпавших LaTeX-строк; отдельная метрика игнорирует только пробелы.
- Эти метрики оценивают распознавание записи, а не математическую правильность решения.
- CPU-бенчмарк измеряет одну подготовленную формулу после прогрева на двух программных потоках.
  Цель 1–2 секунды проверяется измерением, а не считается выполненной заранее; это ещё не реальная квота Space.
- INT8 не выбирается автоматически. `quality_regression_detected` означает, что ускорение ухудшило CER
  или совпадение предсказаний относительно FP32; такой вариант требует дальнейшей проверки.

Обычный английский почерк в исходной модели не равен распознаванию формул. Два тестовых шага
не заменяют полное обучение. Многострочная страница, геометрический чертёж, русский разбор и проверка доказательства
не являются задачами этой OCR-модели; для них будут отдельные части следующего этапа.

## Файлы и локальная проверка разработки

- `data.py` — чтение InkML, подготовка/импорт, preprocessing, целостность и ZIP.
- `ocr.py` — датасет, collator, метрики, Trainer, контроль совместимости checkpoint, экспорт и `push_to_hub`.
- `benchmark.py` — отдельный CPU-процесс; справка: `python -m training.benchmark --help`.
- `requirements-colab.txt` — закреплённые ML-зависимости. PyTorch/torchvision берутся из согласованной среды Colab;
  нужен PyTorch не ниже 2.6 для безопасной загрузки исходного PyTorch bin. Результат сохраняется в safetensors.
- `tools/build_ocr_notebooks.py` — воспроизводимая сборка трёх `.ipynb`, без выводов и секретов.

Быстрые проверки: `python -m unittest discover -s tests -p 'test_*.py'`, `python tools/build_ocr_notebooks.py`.
Зависимости проверок — `tools/requirements-dev.txt`. GPU и скачивание весов для CI не требуются.
Результаты локальной интеграционной проверки описаны в [notes/stage-2-validation.md](../notes/stage-2-validation.md).
